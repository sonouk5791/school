# 디지털 AI 학교 서비스 흐름 통합 결과

## 1. 현재 프로젝트 구조 분석
HTML/CSS/브라우저 JavaScript 기반 다중 페이지 프로젝트다. 루트에서 개발하고 school-release Git 저장소로 동기화한다. Vercel의 api/operations.js가 기관 API, api/tts.js가 기존 Google 음성 연결을 담당한다. automation/은 UI와 분리되어 있다. 기존 자료·저장 키·방 URL은 보존했다.

## 2. 수정한 파일
- index.html: 공통 서비스 모듈 로드, 안내 링크, 미확정 개인정보 문구 정정, 캐시 버전.
- senior-exercise.html, tori-play.html, nabi-learn.html, bori-hobby.html: 공통 정보·기록·콘텐츠 모듈.
- js/home-welcome-flow.js: 캐릭터 이름·역할을 중앙 설정에서 참조.
- js/room-activity-flow.js: 준비 상태, 큰 활동 카드, 추천, 실제 완료 시 공통 결과 저장, 선택 복구.
- js/senior-exercise.js: 기존 일시정지와 공통 활동 시간 측정 연동.
- js/extended-activities.js: 확장 활동의 시작·실제 완료 기록 연동.
- js/senior-common-header.js: 명확한 마을 복귀 문구.
- js/operations-admin.js: 비식별 개별 결과 조회, 안내 활동 편집 연결.
- tests/room-three-stage.cjs: 준비 화면 및 결과 검증 반영.

## 3. 새로 만든 파일
- js/service-config.js: ID별 이름·역할·방 URL·현재 안내 이미지·기존 음성명·활동 메타데이터.
- js/service-activity.js: 독립 활동의 개인정보 없는 결과와 활동 선택 재진입 정보.
- js/service-content.js: 인증된 선생님 화면에서 이 기기의 안내/회상 콘텐츠 추가·수정, 방에서 준비→활동→완료 실행.
- css/service-platform.css: 카드·준비·결과·현재 위치·콘텐츠 화면.
- service-info.html: 개인정보/이용/콘텐츠/문의 안내 구조. 운영 기관과 문의처는 사용자 답변대로 미정.
- tests/service-platform.cjs: 실제 학습 완료, 저장 실패, 콘텐츠 편집 및 실행, 4개 크기 검증.

## 4. 메인 흐름
첫 방문 무음 자동재생, 소리 버튼 시 처음부터 유음 재생, 실제 ended 후 마을 전환, 같은 세션 재방문 시 마을 표시를 유지했다. 강제 대기나 새 팝업을 추가하지 않았다.

## 5. 마을 구현
이전 단계의 하나의 잔디 배경·곡선 길·중앙 쉼터를 유지한다. SVG/CSS 장식과 기존 캐릭터를 사용하며 새 캐릭터나 얼굴을 생성하지 않았다.

## 6. 각 집 연결
콩이 senior-exercise.html, 토리 tori-play.html, 나비 nabi-learn.html, 보리 bori-hobby.html 경로 유지. 기존 추억극장·옛 노래·확장 활동도 유지한다. 공통 상단 메뉴와 완료 화면에 마을 복귀 경로가 있다.

## 7. 활동 공통 흐름
토리/나비/보리 기본 12개 활동은 선택→준비→시작→진행→실제 완료→저장 결과→재시도/다른 활동/마을로 통일했다. 카드에 현재 캐릭터 컷·이름·짧은 설명·예상 시간·쉬움 표시를 넣었다. 시간은 예상치이며 측정 결과와 구분한다. 콩이는 기존 준비/진행/완료 엔진을 유지하며 공통 결과를 붙였다. 기존 정규 수업 iframe에서는 추가 준비 클릭을 강제하지 않는다.

확장 활동은 기존 진행 구조를 보존하고 완료 기록만 연동했다. 모든 과거 하위 페이지의 문제 상태까지 공통 엔진으로 재작성하지는 않았다. 기본 활동 새로고침은 하던 활동의 준비 화면으로 재진입할 수 있으며, 문제별 정답·현재 문제의 정확한 복구는 아직 하지 않는다.

## 8. 기록 저장 구조
기존 기관 기록 digital_school_operations_v3와 도장·보리 미디어 결과 키는 유지한다. 독립 활동은 school_public_activity_results_v1에 ID, 캐릭터, 활동명, 날짜, 활동 시간, 완료율을 저장한다. 이름·대상자 ID·민감 특이사항을 수집하지 않는다. 관찰하지 않은 참여도/기분/도움은 null로 두고 자동 추정하지 않는다. 탭 숨김과 운동 일시정지 시간을 제외한다. 저장 실패는 성공으로 표시하지 않는다. 재호출에 따른 중복 저장을 막는다.

독립 활동은 어느 대상자인지 알 수 없으므로 기관 평가나 AI 일지에 임의로 합치지 않는다. 선생님 공간에서 별도 조회한다. 기관 수업은 기존 대상자 선택→빠른 평가→검토 대기 일지 흐름을 사용한다.

## 9. 관리자 기능
기존 비밀번호 설정·실패 제한·20분 비활동 로그아웃·서버 세션 권한 검사를 보존했다. 프로그램 승인, 대상자, 기록, 초안 보고서, 자동화, 미디어 관리도 유지한다. 새 안내 활동 편집은 인증 UI 내부에 있고, 기관 클라우드 CMS가 아닌 기기 내 초안임을 명시한다. 브라우저 화면 잠금은 서버 권한 관리가 아니다.

## 10. 자동화 연결 상태
기존 서버 엔진은 프로그램 초안→승인→적용, 일/주/월 보고, 재시도·중복 방지 구조를 갖고 있다. 운영 DATABASE_URL과 서버 예약 작업은 아직 연결되지 않았다. 브라우저 타이머로 서버 예약을 가장하지 않는다. GitHub Actions 템플릿은 automation/school-automation.yml.example에 보존되어 있으며 실제 실행 workflow 설치와 secret 설정은 운영자 작업으로 남아 있다.

방의 오늘 추천은 기기 날짜에 따른 기본 활동 순환이다. 승인된 기관 프로그램과 개별 방 추천의 서버 연동은 아직 미완료다.

## 11. DB 구조
PostgreSQL school_operations(id, body jsonb, updated_at) 구조를 그대로 유지한다. body에는 seniors, programs, sessions, participationRecords, dailyReports, weeklyReports, monthlyReports, automationJobs/Logs 등이 있다. 현재 한 배포당 한 기관이다. 다기관 공유 DB의 organizationId 분리·행 수준 권한은 미구현이며, 이 상태로 여러 기관을 같은 저장 영역에 연결하면 안 된다. 마이그레이션·DB 생성·실제 연결은 수행하지 않았다.

## 12. 개인정보 상태
운영 기관/문의처는 미정. 안내는 준비 중으로 게시하고 확정 정책으로 표현하지 않았다. 기존 개인정보 모달의 검증되지 않은 안전 보관·법정 보존기간 확정 문구도 준비 안내로 대체했다. 실제 기관 민감정보를 저장하기 전 서버 접근 제어·보관 기간·위탁 및 삭제 절차를 확정해야 한다. 기존 저장 데이터는 자동 삭제하거나 변환하지 않았다.

## 13. 영상/음악
기존 MP4/WebM 이미지 fallback, 보리 MP4/YouTube·권한 확인·등록 가사·회상/기분 기록 구조 유지. 새 음악이나 외부 검색 이미지를 넣지 않았다. 운동 동작/음악의 새로운 4박/8박 동기화는 이번 작업에서 제작하지 않았다. 기존 Google TTS 파일/API/캐릭터별 연결은 보존했다.

## 14–15. 모바일 및 PC 테스트
1920×1080, 1366×768, 768×1024, 390×844 Edge 자동화에서 준비→날짜 문제 실제 정답→완료 결과→마을 복귀, 카드 수·가로 넘침·오류를 검증했다. 기존 12개 기본 활동, 운동 10동작 완료/도장, 정규 오전 수업/평가/초안, 인증 잠금, 보리 오후 미디어 수업 회귀 테스트 통과. Android/iPhone 실기기 검증은 미실행.

도메인/API 테스트는 트랜잭션 대역이며 실제 PostgreSQL 테스트가 아니다. 실제 Google 합성/AI 보고서 호출도 이번 검증에 포함하지 않았다. 저장 용량 초과 시 실패 안내, 콘텐츠 편집→해당 방 재생→완료도 검증했다.

## 16. 미구현 또는 제한
- 실제 DB·서버 예약·Google AI 보고서 운영 연결, 다기관 권한 분리.
- 기기 내 안내 콘텐츠의 서버 배포/공유 및 모든 게임 문제 편집 CMS.
- 모든 legacy 활동의 동일 준비/결과 엔진과 문제별 정확한 재개.
- 기존 캐릭터 이미지의 모든 구버전 화면까지 일괄 교체는 하지 않음. 원본 보존을 우선했고 현재 메인 및 각 방 이미지를 유지함.
- PWA 설치/오프라인 캐시 미구현. 민감 기관 데이터 캐싱은 도입하지 않음.
- UTF-8 전체 소스 검사에서 js/user-profile.js 보관용 파일의 기존 손상 확인. index.html은 이 파일을 로드하지 않으며 공유 대상자 모듈로 대체된 상태. 손상된 원본은 임의 재구성하지 않음. 나머지 검사 대상 HTML/JS/CSS/API/automation 소스에는 잘못된 UTF-8 또는 U+FFFD 없음.

## 17. 실제 기관 공개 전 남은 작업
기관 운영 주체·문의처·정책 확정, PostgreSQL 연결 및 복구 테스트, 서버 관리자 최초 비밀번호 변경, 예약 실행 계정 권한/secret 등록, 실제 AI/TTS 권한 확인, 콘텐츠 사용권 검증, 실제 태블릿/휴대폰 및 현장 사용자 점검이 필요하다. 코드 변경 배포와 기관 운영 준비 완료는 구분한다.

## 18. 다음 우선순위
1. PostgreSQL 및 서버 인증/예약 연결과 테스트 기관의 가상 데이터 검증.
2. 승인된 프로그램 기반 방 추천 및 콘텐츠 서버 CMS.
3. legacy 개별 활동 공통화·문제별 재개와 실제 기기/현장 QA.
